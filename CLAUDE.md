# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

**Sail Away** (named by the owner; it was "Tradewind" while in development): a 3D sailing game for the browser, on laptop and phone: peaceful sailing, trading and exploring, with ship combat being added in places (see Direction). Plain JavaScript ES modules, Three.js, Vite. There are no asset files at all: geometry, colours, sky, sound and music are generated in code. Keep it that way unless the owner asks otherwise.

The owner is not a programmer. Explain changes in plain language, keep code comments readable by a beginner (the existing files set the tone), and verify behaviour yourself rather than asking them to debug.

**Keep this file up to date.** The owner has asked that CLAUDE.md always reflects important information. Whenever a change adds a feature, alters the architecture, changes a workflow or agreement, or makes something here untrue, update this file (and the README's controls and file tables) in the same commit.

## Commands

```bash
npm install          # once
npm run dev          # dev server with hot reload (http://localhost:5173)
npm run build        # single self-contained dist/index.html (vite-plugin-singlefile inlines everything)
npm run artifact     # build, then strip the html/head/body wrapper into dist/artifact.html for publishing as a Claude Artifact
```

There is no linter and no test suite. Verify changes by building and driving the game in headless Chromium with Playwright against `dist/index.html`:

- Launch with `--use-gl=angle --use-angle=swiftshader --enable-unsafe-swiftshader --ignore-gpu-blocklist` so WebGL works (add `--autoplay-policy=no-user-gesture-required` to test audio).
- Software rendering is slow and frame time is clamped to 0.05 s, so game time runs far slower than wall time. Do not wait on real time; use the test hook instead.
- `window.game` exposes `{ ship, wind, cam, env, audio, shore, places, save, wildlife, people, finds, treasure, combat, vessels, me, fire, world, loot, joinFleet, boardPrize, payWages, home, homePort, layUp, recallShip, sleep, openTrophies, ports, jobs, summonLord, pirateDown, creatures, openSeaLog, refreshTargets, storms, bringStorm, fishing, pressFish, landFish, openFishLog, camera, stick, captain, step, snapCamera, paused, setPaused }` (`jobs` is the whole jobs module; `jobs.target(job)` returns the island or zone a job points at). The camera eases toward its subject and software rendering is slow, so after teleporting the ship or sailor call `game.snapCamera()` (and again just before the screenshot) or the picture will show the camera mid-flight. `game.step(seconds, { steer, sail })` fast-forwards the simulation without rendering. Set state directly (`game.ship.state.x`, `game.env.hour`, `game.env.forced = 0..3` plus `env.w`/`env.sea` for instant weather, `game.cam.yaw/dist/pitch`), then screenshot. `game.audio.level()` returns output RMS.
- Press Enter (or click `#help-go`) to dismiss the help overlay before screenshots.
- To test a ship type, call `game.ship.setType('brig' | 'galleon' | 'sloop')` and set `game.cam.dist = game.ship.type.cam.dist`. To test ashore: place the ship within 110 m of `isl.dock`, set `anchorDown = true`, `game.step(4)`, then press `E` (or click `#action`). Move the sailor by setting `game.shore.state.x/z/heading`, or run `game.shore.update(1/60, { x, z }, false)` in a loop (a world-space direction of length up to 1) to walk without waiting on frames. `game.stick.x/y` can be set to simulate the joystick, but that only acts on real frames. Place doors are in `shore.state.island.portInfo.places` (`doorX`, `doorZ`).
- Progress is stored in localStorage (`tradewind-save`, `tradewind-look`, `tradewind-sound`, `tradewind-compass`, and `sailaway-detail` for the graphics setting); a fresh Playwright page starts clean. The storage keys keep the old name on purpose: renaming them would wipe every player's saved voyage. Setting `env.hour` backwards counts as a new day in the logbook.

- The agreed workflow: develop on a working branch, and only update `main` (the public site) after the owner has seen and approved the change. Update `main` by pushing the working branch to it (`git push origin <branch>:main`); the two are kept identical, with no merge commits.
- Before approval, the owner reviews changes on a private Claude Artifact published from `dist/artifact.html` (`npm run artifact`). Republish to the same artifact so the link stays the same; the URL is in the session where it was created (https://claude.ai/artifact/EEvFVEDz6z7uc1bWuGtUBF), or find it with the Artifact tool's list action ("Sail Away", formerly "Tradewind").
- After pushing to `main`, check the "Publish to GitHub Pages" workflow run finished successfully. The `github-pages` environment only allows deployments from `main` (and the original working branch); a deploy job that fails in seconds with no log means a branch rule is blocking it, which only the owner can change in repo Settings → Environments.
- The cloud sandbox cannot reach `adambabin.github.io`, so the live site cannot be loaded from there; rely on the workflow result and ask the owner to confirm.
- `vite.config.js` uses `base: './'` and a single-file build so the same output works on Pages, from `file://`, and as an Artifact. The Artifact environment blocks external resources except Google Fonts and a few script CDNs, which is another reason nothing loads at runtime.

## Architecture

`src/main.js` owns the scene, input, camera, HUD and the frame loop. Per frame, in order: `env.update` (clock and weather) → `updateWind` (copies `env.windSpeed` into the shared `wind` object and `env.sea` into `sea.state`) → `ship.update` → `shore.update` (only when ashore) → `wildlife.update` → `people.update` → `findAction` and logbook counters → camera → wake → `applyEnvironment` (lights, fog) → `ocean.update` / `sky.update` / `windFx.update` → HUD, place labels, chart → `audio.update` → render. Most cross-module behaviour comes from these shared objects rather than events.

Things that span several files:

- **Waves exist twice and must stay in sync.** `src/waves.js` computes Gerstner wave height on the CPU (ship buoyancy, wake foam, camera floor); the vertex shader in `src/ocean.js` computes the same waves on the GPU. Both read the same wave list (`buildWaves`), the same sea-state multiplier (`sea.state` ↔ `uSea`), and the same calming near islands. Change one, change the other, or the ship will float above or below the visible water.
- **Island shapes exist twice.** `rawCoast()` in `src/islands.js` gives the "coast coordinate" of a point for one piece of land (positive on land, 0 at the shore, negative at sea or in a lagoon); `coast()` in the ocean vertex shader computes the same thing for shallow-water colour, shore foam and wave calming. Change one, change the other. A shape is a wobbly circle (`coastRadius`) optionally stretched along a direction (`stretch`, `rot`), made into a ring or crescent (`inner`, `gap`, `gapHalf`: land between `inner` and the shore, with an opening), or flagged as a reef (never breaks the surface; a shelf 1.6 m down, so a sloop passes and deeper ships ground). `type` picks the height profile and colours: default green, `volcano`, `cliff`, `dark`, `sand`. Land is passed to the shader as three vec4 uniforms each, sized by `MAX_ISLANDS` (60).
- **The world.** `ISLANDS` are the 33 named islands (each has a curiosity, shells, can be landed on, is discovered and charted). The first eleven are the home waters and must stay first and in order, because wobble seeds come from the index. `MINOR` holds unnamed stacks, cays and reefs, each with a `near` island that puts it on the chart. `FEATURES` is both together and is what `terrainHeight`, `islandCoast`, grounding, the ocean shader and other ships use; code about finds, landing, names or the logbook uses `ISLANDS`. `WORLD` is the sea's bounds, `REGIONS` the names written on the chart. To place anything on an island use `islandPoint(isl, angle, r)` and `islandAngle()`, never plain cos and sin from the centre, or stretched islands break; and check `terrainHeight` before trusting a spot on a ring. Ports need a plain island (no stretch or ring) plus entries in `FACTORS`, `TAVERNS` and `KEEPERS` in `trade.js`. `islandGrid(isl)` is a cached coarse raster of an island used by the chart and by treasure maps. `updateIslands()` animates Mount Cinder's smoke.
- **Environment drives everything visual and audible.** `src/environment.js` blends colour keyframes by hour, applies weather (`w` from 0 calm to 1 gale → wind speed, overcast, rain, sea state, foam), and exposes sun/moon/light directions and a `night` factor. Ocean, sky, lights, fog, wind ribbons, rain, night lights and audio all read from the one `env` object. New time-of-day or weather effects should read `env` rather than keep their own state.
- **Paint system.** Meshes are tagged with `paint(mesh, color, opts)` and get materials from `applyPaint(root)` (`src/materials.js`), cached by colour and options. Ship parts carry a `part` tag (`hull`, `trim`, `sail`, `flag`); `ship.setLook()` recolours by part and re-applies paint. The available colours and sail cloths live in `BASIC` (free) and `SPECIAL` (bought at shipwrights) in `src/places.js`; new recolourable parts need a `part` tag, entries in both tables and in `PART_LABELS`, and a default in `look` in `main.js`. Call `applyPaint` after adding painted meshes.
- **Ship conventions** (`src/ship.js`): model forward is +Z, +X is port. `heading` 0 faces +Z (south); world north is −Z. Increasing heading turns to port. Speed = `MAX_SPEED × type.speed × polar(angle to wind − type.pointing) × sail × windFactor`; the `POLAR` table defines the no-go zone. The owner found upwind sailing too slow and chose "a bit kinder" over realism or arcade: the dead zone is `NO_GO` = 22° (plus `type.pointing` for brig and galleon), with half speed at 35° and three-quarters at 45°. They explicitly declined manual sail trimming; the crew trim automatically and that stays. `state.eff` is the current efficiency; below 0.6 with sail set, the HUD shows a hint to bear away and tack. The dial's red wedge is drawn to `NO_GO + type.pointing` for the current ship.
- **Ship types.** `SHIP_TYPES` in `ship.js` holds sloop, brig and galleon: price, hold, handling (`speed`, `turn`, `accel`, `pointing`, `heel`, `draft`), `size` (where the hull meets the water, used for buoyancy, grounding, wake and dolphin spacing via `state.bow/stern/halfBeam`), `cam` (default and minimum camera distance, look-at height) and a `build` function. Hulls come from `makeHull(shape)`; sails from three shared builders, `gaffSail`, `jibSail` and `squareSail`, each returning a per-frame function that reshapes its cloth from one shared context (sail amount, tack, ease, fill, luff). Brig and galleon are both built by `buildSquareRigger` from a data table (`BRIG`, `GALLEON`: hull numbers, raised decks, masts with their sails), so a new square-rigged ship is mostly a new table plus a `SHIP_TYPES` entry. `ship.setType(id)` swaps the model in place and re-applies the last look; `setShip(id)` in `main.js` also updates the save, hold and camera. Anything that measures from the ship should read `ship.type` or `ship.state.bow/stern/halfBeam` rather than assume the sloop's size. Owned ships are in `save.ships`, the current one in `save.shipType`; a ship cannot be swapped to if the cargo aboard would not fit.
- **The captain.** The player's character (`captain` in `main.js`, the same figure as the sailor ashore) stands at the wheel with hands on it, positioned each frame from `ship.helm`. Hidden while ashore (they have gone ashore) and in the deck view (you are looking through their eyes). The owner's rule for now: the player *is* the ship while aboard; there is no walking around on deck.
- **Deck view.** `cam.deck` (View button, V key) switches the camera in `updateCamera()` from the chase view to first person at the wheel. The eye is `ship.helm`, a point in the ship's own coordinates set by each ship's builder (`helm` in the rig, from `helmZ`/`helmUp` for square-riggers), carried through the ship's world matrix so it pitches and rolls with her; the camera's up direction is blended 55% toward the ship's so the horizon tilts gently rather than fully. Dragging turns the head (`cam.lookYaw`, `cam.lookPitch`) instead of orbiting. The near clipping plane drops to 0.35 in this view so nearby rigging is not cut away. Going ashore always uses the third-person view and the deck view resumes on return. The lowest square sails are cut short enough to see the horizon under them from the helm; keep that in mind if sail sizes or helm heights change. Every ship has a wheel in front of the helm that turns with the rudder.
- **Ports and going ashore.** An island becomes a port by having a `port` angle in `ISLANDS`; `buildPort` then creates the dock, houses and the three visitable places and records them in `isl.portInfo` (dock extent, `places` with door positions). Ports must also have an entry in `FACTORS` and `TAVERNS` in `src/trade.js`. `main.js` switches between sailing and ashore via `shore.state.active`: the same `held` input drives either the ship or the sailor (`src/shore.js`), the camera follows whichever is active, and `findAction()` decides the single context action shown on the `#action` button (E key). Walking is limited by `terrainHeight > 0.25`, `onDock`, and the `obstacles` circles from `islands.js`. Going ashore requires the anchor fully down, speed under 1, and the ship within 110 m of the dock end; the row ashore is skipped. Place screens (`src/places.js`) and the chart (`src/chart.js`) are DOM panels that read and write the `save` object (`src/save.js`, persisted to localStorage; the ship's look is stored separately under `tradewind-look`). The ship's position, heading, sail, anchor and the time of day are saved in `save.ship` (every 10 s and when the page is hidden) and restored on load if that spot is still deep water. "Start a new voyage" in the logbook calls `wipe()` and reloads; it asks twice in-page because `confirm()` does not work inside an Artifact.
- **Village people** (`src/people.js`). `buildPerson()` makes every figure, including the player's sailor in `shore.js`. Each port gets three keepers (positions come from the `keeper` offset in `PLACES` in `islands.js`, names from `KEEPERS` in `trade.js`), one fisher on the dock, and three or four villagers who walk between `spots` and refuse to step where the ground is below 0.6 m, so they never wade. Only the port nearest the player (within about 520 m) is shown and updated. Villagers and the fisher are hidden when `env.night > 0.6`; keepers stay. In `findAction()`, standing near a keeper or a place's door opens that place's screen; standing near anyone else offers a greeting (`people.nearby` / `people.greet`, shown as a toast). To test, loop `game.people.update(dt, time, game.env, game.shore.state, game.shore.state)`; `game.people.current.people` lists the figures.
- **Landing anywhere, and things to find** (`src/finds.js`). `shore.land(isl, ship, useDock)` puts the sailor on the dock, or, for any island when no dock is within reach, on the beach nearest the ship (`findAction()` offers "Row to the beach" when the ship is anchored within 110 m of the shoreline). `shore.state.boat` is where the dinghy waits; `atDinghy()` is a distance check. Code that reads `island.portInfo` while ashore must allow for it being undefined. Every island has one curiosity, set by `find: { kind, angle, dist }` in `ISLANDS` (islands.js turns that into `isl.findSpot` and keeps plants off it) and defined in `KINDS` in finds.js (name, button text, logbook text, model, optional `coins`, `reveal` to chart all islands as rumoured, `ring` for the bell sound). Looking at one calls `finds.discover()` and shows a card via `places.show()`. Three shells per island are auto-collected by walking over them. Progress is in `save.finds` and `save.shells`. The bottle on Little Twin points to the chest on The Twins (120 coins); keep that pairing if either moves.
- **Treasure maps** (`src/treasure.js`). A map is `{ id, island, x, z, tier, coins }` in `save.maps` (at most `MAX_MAPS` = 3, one per island at a time). `gainMap()` picks a random dry, open spot (not on a dock, building, curiosity or steep ground) and a tier (`TIERS`: weathered 150–260, fine 300–460, captain's 650–900 coins). Sources: taverns sell one for `MAP_PRICE` (60), and one bottle a day washes up on a beach chosen from the day number (`save.bottleDay` records the last day it was taken; a tavern line names the island). Maps are listed under the chart (`#chart-maps`) and open as a card via `places.card()`, drawn by `treasure.draw()`: coastline, hills, lighthouse, dock and buildings, an X, no name. When the sailor is standing on that island the map also shows a dot for them. Ashore with any map in hand, `findAction()` offers "Dig here" whenever nothing else is on offer; `treasure.dig()` pays out within 5 m of an X, says "close" within 28 m, otherwise nothing. Chests dug up are counted in `save.treasures`. Later stages should hand out maps through `treasure.gainMap()` too (pirate loot).
- **Economy.** Start: 100 coins, the sloop with a 20-crate hold. Seven goods in `GOODS` (salt and obsidian come from the far ports); a port's price is `base × FACTORS[port] × daily wobble`, and merchants pay 92% of the buy price. Tavern trade tips come from `bestRoute()` so they are always true; keep it that way if prices change. Paints cost 25, sail cloth 60, upgrades 150 (hold +10 crates on any ship) and 250 (sails → `speedBonus` 1.1), brig 900, galleon 2800. `applyUpgrades()` in `main.js` turns `save.upgrades` into actual effects.
- **Discovery and the chart** (`src/chart.js`). Sailing within `span × 1.5 + 90` m of an island adds it to `save.discovered` (inked in full); hearing of it in a tavern, or from a lookout curiosity, adds it to `save.rumoured` (a faint ghost and an italic name). The chart sizes itself to the screen (`size()`), sits beside the logbook on wide screens and above it on phones, and has two views: the whole sea, or `NEAR_SPAN` metres around the ship (the Zoom button). Islands are stamped from per-island sprites made from `islandGrid`; reefs are pale patches with crosses; on a small whole-sea view only ports and large islands are named. It also draws region names, pirate waters, nearby ships, a scale bar and the wind.
- **Compass.** A heading strip (`#compass`, C key, Compass button, remembered in localStorage) built in `main.js`: three turns of the compass card side by side, slid by `updateCompass()` to the direction being looked along (ship's head at sea, the camera ashore, the gaze in deck view).
- **Combat** (`src/combat.js`, `src/vessels.js`). Anything that can fight is a *target*: an object with `x, z, y, heading, vx, vz, size, top, guns, reload {port, stbd}, reloadTime, hull (1 → 0), sinking, gone, faction, hit(damage, by)`. The player's ship is wrapped as `me` in `main.js` (getters onto `ship.state` and `ship.type`); every other ship is a vessel from `vessels.js`. `targets = [me, ...vessels.list]`. `combat.fire(shooter, side, targets)` (side 1 = port, −1 = starboard) starts a rippling broadside if that side has reloaded; each gun is laid automatically on the nearest target inside that side's arc (`inArc`: within `RANGE` 170 m and about 41° of straight out), with lead, elevation for range and a little scatter, or fires level if there is none. `combat.update` flies the balls (pooled instanced meshes), tests them against each target's box in the ship's own frame, calls `hit()`, and makes smoke, splashes and the damage smoke of ships below half hull. Damage per ball is `DAMAGE` (9) against `type.hullMax` (sloop 100, brig 220, galleon 400); guns per side come from `gunRow()` in each ship's builder (2, 5, 8) and reload from `type.reload`. Hull damage slows a ship and sets her lower in the water (`ship.update`). The player's hull is `ship.state.hull`, saved in `save.ship.hull`; at 0 `state.sinking` starts counting, the ship rolls under, and after 7 s `lostAtSea()` clears the cargo, removes the lost ship from `save.ships` (a sloop is always replaced), and restarts the player anchored at `HOME` off Port Marigold. Shipwrights repair for 0.6 coins a point; at anchor the crew patch up to 60%. Vessels are built with `buildNpcModel()` (the player's ship builders with sails set once, so they are cheap), are hidden beyond 2600 m, and are replaced by a newcomer a minute or two after sinking. Other ships' gunnery is deliberately weaker than the player's (`aim` 2.1 widens scatter, `power` 0.55 scales damage, reload ×1.5) so fights are winnable; with these numbers a sloop that sits still in pirate waters lasts about 70 s and loses to the pair there, a brig wins narrowly, a galleon comfortably. Retune there, not in the player's guns.
- **Factions** (`src/factions.js`, behaviour in `vessels.js`). Twenty vessels sailing in companies (set up by `company(leader, ...followers)`): two merchant convoys of three, each with a navy sloop as `escort`; two navy patrols of two brigs; and a pirate squadron (brig leading a sloop) in each of the four `ZONES` (pirate waters, drawn on the chart). Honest ships sail from port to port (`offAPort()`); pirates stay in their zone; any ship past the edge of `WORLD` turns back for the middle. A follower with nothing to fight keeps station on her `leader` using the same code as the player's fleet, adopts her leader's enemy, and sails independently if the leader is lost; an escort attacks whoever has alarmed her convoy, and a hit on one merchant scatters them all. Every 6 to 10 minutes `raid()` sends the navy patrol into one zone for about four minutes, which produces a battle; `listenForBattle()` in `main.js` announces it once, with a compass bearing, when the player is within 1300 m. A pirate the player has hit in the last 90 s (`assist`) pays half her bounty if someone else sinks her. As a last resort any vessel within the shallows is pushed back out, so fights near land cannot ground a ship. Keep pirate zones well clear of islands (Deadman's Reach was moved for this). `chooseEnemy()` runs about once a second per ship: pirates fight the player only while the player is inside their zone (or for 90 s after being fired on, `provoked`) and otherwise any navy ship close by; the navy fights pirates within 450 m and the player only when wanted or provoked; merchants never fight and flee for 45 s when hit. Nobody targets or damages the player's ship while the player is ashore. A fighting ship closes to gun range, turns beam-on and holds there, firing whichever side bears; she runs below 20% hull. Honest ships plot courses that avoid pirate waters. Reputation is one number, `save.wanted` (0–5): a hit on a merchant raises it to at least 1, on the navy to at least 2, sinking adds 1.5 or 2; it drops by 1 each new day (`coolOff`) or to 0 by paying `fine()` (120 coins a level) at any market. While wanted, markets charge up to 40% more and pay up to 40% less (`priceUp`/`priceDown`). `save.piratesSunk` counts kills. The `fx.struck`/`fx.sunk` callbacks in `main.js` are where consequences are applied; `updateDangers()` shows the pirate-waters toasts, the Wanted chip and the tag over the nearest ship. Test hooks: `game.combat`, `game.vessels.list`, `game.me`, `game.fire(side)`; `game.step()` also advances vessels and cannonballs.
- **Spoils** (`src/loot.js`). `fx.sunk` in `main.js` calls `loot.drop(v, withMap)` for every ship that sinks: merchants leave two or three lots of cargo and a cash box, others a sea chest (pirates sometimes plundered cargo too), sized by ship type; a pirate the player sank has a 35% chance of a map bottle if the player has room for one. Flotsam drifts downwind and lasts 240 s. `loot.update` hands anything within `bow + 5` m of the ship to `salvage()` in `main.js`, which adds coins, cargo (as much as fits; a full hold leaves it floating) or a map via `treasure.gainMap()`. Each pirate vessel has a `captain` (from `newCaptain()`) and a `bounty` (`BOUNTY` by ship type: 160 / 320 / 700); a replacement pirate gets a new captain. Sinking one adds the bounty to `save.bountyDue`; every tavern screen shows the board of captains at large and a Collect button, which is disabled while wanted. `save.bountyPaid` is the running total.
- **Surrender, prizes and the fleet** (`vessels.js`, the fleet and prize sections of `main.js`). A non-fleet ship that the player's side (the player or their fleet) batters below `STRIKES_AT` (merchant 30%, navy 16%, pirate 18% hull) sets `v.struck` (150 s countdown): she stops, fires at nobody and nobody fires at her. Hitting her again still damages and can sink her; left alone she slips away. Within about 60 m and under 4.5 m/s, `findAction()` offers "Board", and `boardPrize(v)` shows four choices: take her (the player's ship becomes her type at her hull; the old ship is sold for `shipValue`, or kept if it is the sloop), add her to the fleet (needs hull ≥ 10% and fewer than `MAX_FLEET` = 3), strip and sink her, or let her go. Taking a pirate pays her bounty; taking an honest ship raises `wanted`. The original vessel is marked `gone` so a replacement arrives later. Fleet ships are vessels with `faction: 'player'`, `fleet: true`, built in the player's colours by `vessels.addFleet()`. With no enemy they keep station astern of the flagship by `slot`, rubber-banding their speed so they are never left behind; `pickFleetEnemy()` sets `world.fleetEnemy` each frame (a ship hunting the player or the fleet, or the one the player last hit) and they fight it with the usual fight logic. Hostile ships choose the nearest of the player and the fleet. The player's own broadsides never auto-aim at fleet ships. `save.fleet` (`{ type, hull }`) is kept in step by `syncFleet()`, which also recomputes the hold (flagship + upgrade + every fleet ship's hold) and discards cargo that no longer fits. `payWages()` runs each new day (`WAGES`: 15 / 30 / 60 coins); if the purse is short the last ship to join leaves. If the flagship sinks and a fleet ship survives, `lostAtSea()` makes that ship the flagship where she lies instead of sending the player home. Shipwrights list the fleet with Repair and Sell. `targets` is rebuilt by `refreshTargets()` whenever a vessel is added or removed (`fx.left`). Test hooks: `game.joinFleet(type, hull, at)`, `game.boardPrize(v)`, `game.payWages()`, `game.vessels.fleet()`.
- **Tavern jobs** (`src/jobs.js`). Every tavern offers three jobs a day, generated by `offers(isl, day)` from a random-number generator seeded by port name and day, so the list is stable through the day. The first two are always peaceful (freight for another port, a passenger); the third is a pirate hunt in one zone, a "collector" job (find the curiosity on a named island) or a "survey" job (discover a named island). At most `MAX_JOBS` = 3 in hand, kept in `save.jobs`; `save.jobsTaken` stops today's offers reappearing. Freight sits in the hold as `save.cargo.freight` (not a trade good: markets ignore it, `cargoCount()` includes it), so it is lost with the ship (`loseFreight()` in `lostAtSea()`) and can be squeezed out when the fleet shrinks (`freightLost`). Freight and passengers are paid at the destination's tavern; the others at any tavern once done (`isDone` reads `save.finds` / `save.discovered`; hunts are flagged by `pirateBeaten(zoneName)`). The owner chose **name and direction only**: a job says "Ringtown, far to the east" (`whereabouts()`), never marks the chart or compass, and never adds the island as rumoured. The logbook lists jobs in hand with the direction from the ship. Keep peaceful work always on offer.
- **Pirate lords** (`LORDS` in `factions.js`, one per zone in the same order as `ZONES`). `save.lords[zone.name]` is `{ sunk, beaten }`. `pirateDown(v)` in `main.js` is called whenever the player's side sinks or takes a pirate (or shares the kill): it settles hunt jobs and adds to `sunk`. At `LORD_AFTER` (3), whenever the player is in that zone and no lord is afloat there, `updateDangers()` calls `summonLord(zone)` → `vessels.addLord()`: a galleon in the lord's own colours on the far side of the zone, `lord: true`, bounty `LORD_BOUNTY` (1500), stouter and a better shot than ordinary ships (`tough` 1.3, `aim` 1.8, `power` 0.62), with the local squadron as her followers. - **Earned rewards** (`src/rewards.js`). `REWARDS` holds things that cannot be bought: looks (`look: [part, value]`, which `grant()` adds to `save.owned` so they appear at every shipwright; `EARNED_LOOKS` feeds `ALL_LOOK_VALUES`) and fittings (`fit: true`, checked with `hasReward(id)`: quick-match reload ×0.8 and long guns damage ×1.2 on `me`, ironwood damage taken ×0.8 in `me.hit`, storm rig and coppered bottom in `applyUpgrades()` via `speedBonus` / `turnBonus`, seasoned crew in the anchor patching in `frame()`). - **Fishing** (`src/fishing.js`, wired up in the fishing section of `main.js`). The hook button (`#btn-fish`, F key) is pressed to cast, pressed again to strike when the float dips, and *held* to reel in, so it listens for pointerdown/up (and F keydown/keyup) rather than click; `fishHeld` is the held state. `fishing.state.state` runs idle → waiting → bite (1.4 s to strike, or it is missed and the line stays out) → reeling. Reeling is a one-button tug-of-war: holding raises `tension` and `landed`; the fish makes runs (`surge`) during which holding strains the line hard and letting go loses a little ground; `tension` ≥ 1 snaps the line, 2.5 s of slack lets the fish shake the hook, `landed` ≥ 1 lands it. With these numbers an angler who eases off on runs lands about three in four; one who ignores runs snaps nearly every line. The ship must be under 2.4 m/s (sail down or anchored), or the line comes in. `FISH` lists 16 kinds with `where` conditions (near land within 160 m, open water beyond 260 m, a region from `REGIONS`, day, night, far from home, storm), `odds`, `fight`, weight range and base `price`; `waterAt()` describes a spot and `pickFish()` draws from what bites there. The oarfish bites only when `env.w > 0.85` (a gale; storms will make this more common). Landed fish go into the hold as cargo under `fish_<id>` (so they count against the hold and are lost with the ship) and are sold in a Fish section of every market at `fishPrice(port, fish, day)` (each port's own taste, drifting daily); markets never sell fish. `save.fishLog[id] = { n, best }`; the Fish log card (button under the chart, `openFishLog()`) lists every kind with where it bites, greyed until caught. `LOG_REWARDS` grants earned rewards at 4, 8, 12 and 16 kinds (fine tackle: bites come sooner; marlin-blue hull; fish-scale sail cloth; strong line: less strain). Taverns can offer a fish job (the cook wants a named fish brought back to that tavern; `jobs.status()` gives the keeper's progress line). While a fish is biting or on the line, `findAction()` offers nothing, so the big button cannot take you ashore mid-fight. On phones the four round buttons sit two by two, and the hint, reel gauge and action button sit above them.
- **Storms** (`src/storms.js`, the storms section of `main.js`). At most one storm at a time: `{ x, z, r (400–520 m), vx, vz, age, life (8–11 min) }`. The first builds 5–12 minutes after loading, later ones 12–22 minutes after the last ends, 1.8–2.6 km upwind of the player so the wind carries it toward them at about 3 m/s; it builds over its first minute and dies away over its last. `storms.at(x, z)` is its force at a point (full within half its radius, nothing beyond 1.1×). `updateStorms()` runs *before* `env.update` each frame and eases `env.storm` toward the force where the ship (or sailor) is; `environment.js` then treats the weather as at least a gale (`W = max(w, storm)`), adds wind, rain, overcast, darkness, a shorter fog and higher seas (`sea` up to about 2.15; the five waves' steepness adds up to 0.43, so even then the Gerstner waves do not fold over). It is drawn as a dark cloud mass over a rain curtain (visible up to 6 km, fogged by distance), with lightning bolts that set `env.flash` (brightens sky and light for a moment) and call `audio.thunder(distance)`, delayed by distance. Notices: "building" (with a compass direction, within 2.8 km), "inside", "passed"; the usual wind-change toast is muted in a storm. **Danger:** `storms.strain()` costs hull while the ship is at sea (not anchored) with more than `SAFE_SAIL` (50%) sail where the storm's force is over 0.35: up to `STRAIN` (0.45% of the hull a second) at full sail at the heart, about 2.5 minutes from sound to the floor; it never takes the hull below `FLOOR` (25%), so a storm alone cannot sink a ship. The hint line warns, then reassures under short sail; strained timbers make crunching sounds. The chart shows a storm within 3.2 km. The oarfish bites when `env.storm > 0.45` (or a natural gale). Test hooks: `game.storms` (`current`, `spawn(near, wind, far)`, `at`, `state`), `game.bringStorm()`, and the pause menu's "Bring a storm" testing button. Other ships ignore storms.
- **Sea creatures** (`src/creatures.js`, the creatures section of `main.js`). `CREATURES` lists the 12 entries of the sea-life log: nine real animals spawned here (humpback, sperm whale, orca pod, green turtle, manta, hammerhead, whale shark, monk seals, glowing jellyfish at night), dolphins (logged when the existing `wildlife.pod` from `wildlife.js` comes within 60 m), and the two legends. Each real kind has `where` conditions in the same words as the fish (it reuses `waterAt()` from `fishing.js`; `region` may be a list), a log `range` and `odds`; `MOVES` gives its model builder (procedural, painted with `paint()`), surface/dive timings, speed, and extras (`blow` spout, humpback `breach`, manta `leap`, `pod` size, `always` at the surface, `circle`, `shore` leash). Every 45 to 90 s at sea, if fewer than two groups are out, `trySpawn()` puts an eligible animal 300 to 560 m ahead (never in The Deep), favouring unlogged kinds; it lives 3 to 4 minutes or until 1.7 km away. Ocean water is opaque, so a submerged model is simply hidden. Being within `range` while one is up logs it (`save.creatures[id]` counts sightings; the brass spyglass reward ×1.6 range); a first sighting further off gives a "Thar she blows! A spout to the north-east" notice. `LOG_REWARDS` at 4, 8 and 12 kinds: spyglass, coral sails, wave-crest sail cloth. **Legends** are cannon targets (same shape as a vessel: `faction: 'monster'`, `hull`, `hit()`, `size`, `gone` while submerged so balls pass through) and are added to `targets` by `refreshTargets()` while out; the fleet fights them when no ship is hostile (`pickFleetEnemy`), and the vessel tag and fire-button highlight include them. **The Kraken** lives in `DEEP` (−1350, 1500, r 340 m, open water west of The Twins; drawn on the chart as a dark dashed ring, "here be monsters" until beaten). Sailing in starts a 6 to 10 s timer, then it rises abeam: six arms rise along the ship's sides and one slams down every 4.5 to 6.5 s (8 damage through `me.hit`, so ironwood helps), and every 22 to 28 s it sinks and comes up on the other side. 460 hull points. **The Sea Serpent** may rise (60%, once per storm, `serpentRolled` on the storm object) when the player is in a storm (`env.storm` > 0.5) more than 2 km from home; it circles at 58 m and lunges every 7 to 9.5 s (8 damage); 360 points; it leaves when the storm passes. Either leaves if the player gets 700 m away, goes ashore or sinks, and returns next time; they are not saved mid-fight. Measured, sitting still and firing every broadside: a sloop loses to both; a brig beats the kraken with about half her hull left and the serpent with about a quarter; a galleon wins both easily. Beating one sets `save.legends[id]`, pays `LEGEND_COINS` (1200 / 1000) and grants `LEGEND_REWARDS` (kraken-ink sails, serpent-jade trim); both together grant the Leviathan figurehead (storms strain her half as much, in `storms.strain()`). Taverns now rumour both legends and whales. The Sea-life log card (button under the chart, `openSeaLog()`) lists all twelve with where they are found. Sounds: `audio.roar()`. Test hooks: `game.creatures` (`active`, `legend`, `spawnAhead(id, ship, d)`, `summon(id, ship)`, `log(id)`), `game.openSeaLog()`, `game.refreshTargets()`, and the pause menu's "Show a sea creature" testing button.
- **Home port** (`src/home.js`, the home-port section of `main.js`, `house()` in `places.js`). Every port reserves six level plots (`portInfo.lots`, found by `homeLots()` in `islands.js` before trees are planted: above the beach, off the path up from the dock, clear of houses and doors, nearest the dock first) and up to four deep-water `portInfo.moorings` beside the dock; every port's plots were checked reachable on foot with a route search. Any tavern offers "A house for sale" (`HOME_PRICE` 600) or "Move your home here" (`MOVE_PRICE` 300; buildings, stores and laid-up ships move too, because they are only data). `save.home` = `{ port, built, store, moored, pending }`. `createHome().rebuild()` puts up the house (lot 0, your flag on it) and whatever is built from `BUILDINGS` (each with `cost`, `lot`, and `makes` for businesses): warehouse (300, holds `WAREHOUSE_SPACE` 100 crates of goods or fish), moorings (250), trophy hall (350; flags of beaten lords out front), fish smokehouse (400, 35 coins a day; its chimney smokes), plantation (700, 4 crates a day of whichever of mango, timber or spice is cheapest there), rum distillery (1100, 3 crates of rum a day). **Phones** (the polish pass). `body.touch` is set in `main.js` when the pointer is coarse (a touch screen): the help card then shows the touch list (`.touch-only`) instead of the keys (`.keys-only`); its words scroll in `.help-body` while Set sail stays in `.help-foot`. Every tappable thing on a touch screen is at least about 40 px (`@media (pointer: coarse)` and the `max-width: 560px` block). On narrow screens the wind dial is smaller and notices (`#toast`) sit below it; a phone held sideways (`max-height: 520px` and landscape) gets near-full-height sheets, a two-column pause menu, and the chart beside the logbook (`size()` in `chart.js` treats it as wide). **Graphics:** `detail` is `light` on touch screens and `full` otherwise, saved in `sailaway-detail` and switched from the pause menu (it saves and reloads, because the sea is built once). Light means no antialiasing, a pixel ratio capped at 1.5 instead of 2, and a 150-square sea grid instead of 220 (`createOcean(waves, features, N)`; the fine inner part scales with N). Measured at a 390×844 screen at 3× density: 44% fewer pixels, about 20% fewer triangles, and 2.6 times the frame rate in software rendering. **Menus** (owner's request after testing on an iPhone, where a long menu's Leave button scrolled out of reach): every `.sheet` (place screens and cards in `#place`, the chart in `#chart`) is a flex column of a fixed `.sheet-head`, a scrolling middle (`#place-body`, `#chart-body`) and a `.sheet-foot` with a full-width Leave or Close button, shown on touch screens only; `places.js` `reveal()` sets the close wording (Leave for places, Close for cards) and scrolls to the top. On phones a sheet fits between the notch and the home bar (`env(safe-area-inset-*)`, `100dvh`). The pause card is the same: `.pause-head`, scrolling `.pause-body`, and Resume pinned in `.pause-foot`. **Sound on iPhone:** sound may only start from a gesture, and iPhones only count a finished tap, so `audio.start()` listens on pointerdown, pointerup, touchend, click and keydown, plays a one-sample buffer the first time, and resumes the context if it is suspended or interrupted. The iPhone silent switch mutes Web Audio unless the page plays as media: `playThroughSilentMode()` sets `navigator.audioSession.type = 'playback'` where available and otherwise keeps a half-second of silence (a WAV built in code) looping in an `<audio>` element; it is paused with the game. Also in `index.html`: a theme colour, home-screen app tags, and a small sail icon drawn as an inline SVG. Test hooks: `game.detail`, `game.renderer`. To test touch layouts, open the page with Playwright's `isMobile: true, hasTouch: true` at 390×844, 360×640 and 844×390.

The HUD and all CSS live in `index.html`; elements toggle with the `hidden` attribute (there is an explicit `[hidden] { display: none !important }` rule because several are `display: grid/flex`). **Input.** One on-screen joystick (`#stick`, state in `stick`) and the keyboard (`held`) are combined each frame by `readPush()` into `push` (`x`: right +, left −; `y`: up +, down −, each −1 to 1). At sea `push.x` steers and `push.y` raises or lowers sail. Ashore the push is turned into a ground direction measured from where the camera looks (`walkMove`), the sailor turns to face the way they walk, and pushing left or right also swings the camera (`cam.follow -= push.x × 1.5 × dt`), so one stick walks and turns. Dragging the screen still orbits the camera. New controls should work from both the stick or an on-screen button and a key. Keys: A/D/W/S or arrows (steer and sails, or walk ashore), Space anchor, E context action, F fish (hold to reel), M map and logbook, C compass, 1 / 2 fire port / starboard, V deck view, T skip three hours, R cycle weather, B try the next ship (temporary), N sound mode, Escape pause. **Pause** (`setPaused()` in `main.js`, the `#pause` overlay, Escape or the II button): Escape first closes whatever is open (help, a place screen, the chart) and only pauses when nothing is. While `paused`, `frame()` draws but updates nothing, sound is suspended, the game is saved, and every key except Escape or Enter (resume) is ignored. ### Second plan: treasure, combat, factions and fleets

Decisions the owner made (do not re-ask; build to these):

- **Combat tone: danger in places.** Most of the sea stays peaceful. Pirates keep to their own marked waters. Navy and merchants never attack unless the player attacks them (or is wanted).
- **If the player loses: the ship sinks** with her cargo. The player restarts at port in the sloop and keeps coins and any other ships owned.
- **Cannons: broadsides.** Guns fire out of each side; the player steers to bring a side to bear and presses Fire Port or Fire Starboard. Reload time between broadsides.
- **Factions with reputation:** merchants, navy, pirates. Sinking pirates pleases navy and ports. Attacking merchants makes the player wanted: navy hunts them and prices worsen, until a fine is paid or it fades.
- **Spoils:** floating coins and cargo to sail over; navy bounties on named pirate captains, collected at any harbour; pirates sometimes carry treasure maps; captured ships.
- **Capture: surrender, then claim.** A ship beaten to low health strikes her colours and stops. Sail alongside for a choice: take her as your ship (selling the current one), add her to your fleet if not too damaged, strip her for loot, or let her go. Keep firing and she sinks.
- **Player's fleet:** flagship plus up to three ships that follow in her wake and automatically fight whoever the player is fighting. No orders. Each costs a daily wage; their holds add cargo space.
- **NPC fleets:** pirate squadrons led by a named captain with a bounty, navy patrols, merchant convoys (sometimes escorted), and battles already under way that the player can join or sail past.
- **Treasure maps: a drawn map.** A hand-drawn sketch of one island's outline with an X and a landmark or two, no name. The player works out which island it is and digs at the X.
- **While aboard the player is the ship:** they command and fire but do not walk the deck. Crew figures may be shown doing things. The captain stands at the wheel.
- **Mobile:** one joystick with a following camera (done in stage 1).

### Third plan: life at sea and a home port

The owner is play-testing and retuning the existing game alongside this. Decisions (do not re-ask):

- **Fishing: bite and strike.** Cast, strike when it bites, a short one-button tug-of-war to land it. Fish differ by waters and time of day. Fish sell at markets, fill a fish log that earns rewards, and can be asked for in tavern jobs.
- **Storms: mild danger.** Rare storms you can see coming (dark wall, lightning, thunder, towering seas, heavy rain). Carrying full sail in one strains the ship and slowly damages the hull; shorten sail or anchor and you are safe. A storm never sinks the ship outright. This deliberately relaxes the earlier "weather is never a threat" rule, for storms only; ordinary gales stay harmless.
- **Sea creatures: legends you can fight.** Mostly real animals (whales, turtles, rays, orcas, sharks, seals and so on) to find and log, each in its own waters, plus a legendary monster or two that attack the ship and can be fought like a pirate lord.
- **Home port: in any existing port the player chooses.** Buildings: a warehouse (store cargo), moorings for spare ships (owned ships wait there; fleet ships can be left there without wages), earning businesses (make goods or coins daily, collected on a visit) and a trophy hall (fish, creatures, lords' flags, treasure; display only).
- **Order:** fishing, then storms, then creatures, then the home port. Each is reviewed on the private link before going to `main`.
