# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

"Tradewind" (working title): a 3D sailing game for the browser, on laptop and phone: peaceful sailing, trading and exploring, with ship combat being added in places (see Direction). Plain JavaScript ES modules, Three.js, Vite. There are no asset files at all: geometry, colours, sky, sound and music are generated in code. Keep it that way unless the owner asks otherwise.

The owner is not a programmer. Explain changes in plain language, keep code comments readable by a beginner (the existing files set the tone), and verify behaviour yourself rather than asking them to debug.

**Keep this file up to date.** The owner has asked that CLAUDE.md always reflects important information. Whenever a change adds a feature, alters the architecture, changes a workflow or agreement, or makes something here untrue, update this file (and the README's controls and file tables) in the same commit.

## Commands

```bash
npm install          # once
npm run dev          # dev server with hot reload (http://localhost:5173)
npm run build        # single self-contained dist/index.html (vite-plugin-singlefile inlines everything)
npm run artifact     # build, then strip the html/head/body wrapper into dist/artifact.html for publishing as a Claude Artifact
```

There is no linter and no test suite. Verify changes by building and driving the game in headless Chromium with Playwright against `dist/index.html`:

- Launch with `--use-gl=angle --use-angle=swiftshader --enable-unsafe-swiftshader --ignore-gpu-blocklist` so WebGL works (add `--autoplay-policy=no-user-gesture-required` to test audio).
- Software rendering is slow and frame time is clamped to 0.05 s, so game time runs far slower than wall time. Do not wait on real time; use the test hook instead.
- `window.game` exposes `{ ship, wind, cam, env, audio, shore, places, save, wildlife, people, finds, camera, step, snapCamera }`. The camera eases toward its subject and software rendering is slow, so after teleporting the ship or sailor call `game.snapCamera()` (and again just before the screenshot) or the picture will show the camera mid-flight. `game.step(seconds, { steer, sail })` fast-forwards the simulation without rendering. Set state directly (`game.ship.state.x`, `game.env.hour`, `game.env.forced = 0..3` plus `env.w`/`env.sea` for instant weather, `game.cam.yaw/dist/pitch`), then screenshot. `game.audio.level()` returns output RMS.
- Press Enter (or click `#help-go`) to dismiss the help overlay before screenshots.
- To test a ship type, call `game.ship.setType('brig' | 'galleon' | 'sloop')` and set `game.cam.dist = game.ship.type.cam.dist`. To test ashore: place the ship within 110 m of `isl.dock`, set `anchorDown = true`, `game.step(4)`, then press `E` (or click `#action`). Move the sailor by setting `game.shore.state.x/z/heading`, or run `game.shore.update(1/60, { x, z }, false)` in a loop (a world-space direction of length up to 1) to walk without waiting on frames. `game.stick.x/y` can be set to simulate the joystick, but that only acts on real frames. Place doors are in `shore.state.island.portInfo.places` (`doorX`, `doorZ`).
- Progress is stored in localStorage (`tradewind-save`, `tradewind-look`, `tradewind-sound`); a fresh Playwright page starts clean. Setting `env.hour` backwards counts as a new day in the logbook.

## Deployment and branches

- Pushing to `main` triggers `.github/workflows/pages.yml`, which builds and deploys to GitHub Pages: https://adambabin.github.io/sailing-game/
- The agreed workflow: develop on a working branch, and only update `main` (the public site) after the owner has seen and approved the change. Update `main` by pushing the working branch to it (`git push origin <branch>:main`); the two are kept identical, with no merge commits.
- Before approval, the owner reviews changes on a private Claude Artifact published from `dist/artifact.html` (`npm run artifact`). Republish to the same artifact so the link stays the same; the URL is in the session where it was created, or find it with the Artifact tool's list action ("Tradewind").
- After pushing to `main`, check the "Publish to GitHub Pages" workflow run finished successfully. The `github-pages` environment only allows deployments from `main` (and the original working branch); a deploy job that fails in seconds with no log means a branch rule is blocking it, which only the owner can change in repo Settings → Environments.
- The cloud sandbox cannot reach `adambabin.github.io`, so the live site cannot be loaded from there; rely on the workflow result and ask the owner to confirm.
- `vite.config.js` uses `base: './'` and a single-file build so the same output works on Pages, from `file://`, and as an Artifact. The Artifact environment blocks external resources except Google Fonts and a few script CDNs, which is another reason nothing loads at runtime.

## Architecture

`src/main.js` owns the scene, input, camera, HUD and the frame loop. Per frame, in order: `env.update` (clock and weather) → `updateWind` (copies `env.windSpeed` into the shared `wind` object and `env.sea` into `sea.state`) → `ship.update` → `shore.update` (only when ashore) → `wildlife.update` → `people.update` → `findAction` and logbook counters → camera → wake → `applyEnvironment` (lights, fog) → `ocean.update` / `sky.update` / `windFx.update` → HUD, place labels, chart → `audio.update` → render. Most cross-module behaviour comes from these shared objects rather than events.

Things that span several files:

- **Waves exist twice and must stay in sync.** `src/waves.js` computes Gerstner wave height on the CPU (ship buoyancy, wake foam, camera floor); the vertex shader in `src/ocean.js` computes the same waves on the GPU. Both read the same wave list (`buildWaves`), the same sea-state multiplier (`sea.state` ↔ `uSea`), and the same calming near islands. Change one, change the other, or the ship will float above or below the visible water.
- **Island coastline also exists twice.** `coastRadius`/`coastOf` in `src/islands.js` (terrain mesh, collision via `terrainHeight`, wave calming) is mirrored by `coast()` in the ocean shader (shallow-water colour, shore foam). Islands are passed to the shader as uniforms sized by `MAX_ISLANDS` (12); the `ISLANDS` list must not exceed it. Adding an island is one entry in that list.
- **Environment drives everything visual and audible.** `src/environment.js` blends colour keyframes by hour, applies weather (`w` from 0 calm to 1 gale → wind speed, overcast, rain, sea state, foam), and exposes sun/moon/light directions and a `night` factor. Ocean, sky, lights, fog, wind ribbons, rain, night lights and audio all read from the one `env` object. New time-of-day or weather effects should read `env` rather than keep their own state.
- **Paint system.** Meshes are tagged with `paint(mesh, color, opts)` and get materials from `applyPaint(root)` (`src/materials.js`), cached by colour and options. Ship parts carry a `part` tag (`hull`, `trim`, `sail`, `flag`); `ship.setLook()` recolours by part and re-applies paint. The available colours and sail cloths live in `BASIC` (free) and `SPECIAL` (bought at shipwrights) in `src/places.js`; new recolourable parts need a `part` tag, entries in both tables and in `PART_LABELS`, and a default in `look` in `main.js`. Call `applyPaint` after adding painted meshes.
- **Ship conventions** (`src/ship.js`): model forward is +Z, +X is port. `heading` 0 faces +Z (south); world north is −Z. Increasing heading turns to port. Speed = `MAX_SPEED × type.speed × polar(angle to wind − type.pointing) × sail × windFactor`; the `POLAR` table defines the no-go zone.
- **Ship types.** `SHIP_TYPES` in `ship.js` holds sloop, brig and galleon: price, hold, handling (`speed`, `turn`, `accel`, `pointing`, `heel`, `draft`), `size` (where the hull meets the water, used for buoyancy, grounding, wake and dolphin spacing via `state.bow/stern/halfBeam`), `cam` (default and minimum camera distance, look-at height) and a `build` function. Hulls come from `makeHull(shape)`; sails from three shared builders, `gaffSail`, `jibSail` and `squareSail`, each returning a per-frame function that reshapes its cloth from one shared context (sail amount, tack, ease, fill, luff). Brig and galleon are both built by `buildSquareRigger` from a data table (`BRIG`, `GALLEON`: hull numbers, raised decks, masts with their sails), so a new square-rigged ship is mostly a new table plus a `SHIP_TYPES` entry. `ship.setType(id)` swaps the model in place and re-applies the last look; `setShip(id)` in `main.js` also updates the save, hold and camera. Anything that measures from the ship should read `ship.type` or `ship.state.bow/stern/halfBeam` rather than assume the sloop's size. Owned ships are in `save.ships`, the current one in `save.shipType`; a ship cannot be swapped to if the cargo aboard would not fit.
- **The captain.** The player's character (`captain` in `main.js`, the same figure as the sailor ashore) stands at the wheel with hands on it, positioned each frame from `ship.helm`. Hidden while ashore (they have gone ashore) and in the deck view (you are looking through their eyes). The owner's rule for now: the player *is* the ship while aboard; there is no walking around on deck.
- **Deck view.** `cam.deck` (View button, V key) switches the camera in `updateCamera()` from the chase view to first person at the wheel. The eye is `ship.helm`, a point in the ship's own coordinates set by each ship's builder (`helm` in the rig, from `helmZ`/`helmUp` for square-riggers), carried through the ship's world matrix so it pitches and rolls with her; the camera's up direction is blended 55% toward the ship's so the horizon tilts gently rather than fully. Dragging turns the head (`cam.lookYaw`, `cam.lookPitch`) instead of orbiting. The near clipping plane drops to 0.35 in this view so nearby rigging is not cut away. Going ashore always uses the third-person view and the deck view resumes on return. The lowest square sails are cut short enough to see the horizon under them from the helm; keep that in mind if sail sizes or helm heights change. Every ship has a wheel in front of the helm that turns with the rudder.
- **Ports and going ashore.** An island becomes a port by having a `port` angle in `ISLANDS`; `buildPort` then creates the dock, houses and the three visitable places and records them in `isl.portInfo` (dock extent, `places` with door positions). Ports must also have an entry in `FACTORS` and `TAVERNS` in `src/trade.js`. `main.js` switches between sailing and ashore via `shore.state.active`: the same `held` input drives either the ship or the sailor (`src/shore.js`), the camera follows whichever is active, and `findAction()` decides the single context action shown on the `#action` button (E key). Walking is limited by `terrainHeight > 0.25`, `onDock`, and the `obstacles` circles from `islands.js`. Going ashore requires the anchor fully down, speed under 1, and the ship within 110 m of the dock end; the row ashore is skipped. Place screens (`src/places.js`) and the chart (`src/chart.js`) are DOM panels that read and write the `save` object (`src/save.js`, persisted to localStorage; the ship's look is stored separately under `tradewind-look`). The ship's position, heading, sail, anchor and the time of day are saved in `save.ship` (every 10 s and when the page is hidden) and restored on load if that spot is still deep water. "Start a new voyage" in the logbook calls `wipe()` and reloads; it asks twice in-page because `confirm()` does not work inside an Artifact.
- **Village people** (`src/people.js`). `buildPerson()` makes every figure, including the player's sailor in `shore.js`. Each port gets three keepers (positions come from the `keeper` offset in `PLACES` in `islands.js`, names from `KEEPERS` in `trade.js`), one fisher on the dock, and three or four villagers who walk between `spots` and refuse to step where the ground is below 0.6 m, so they never wade. Only the port nearest the player (within about 520 m) is shown and updated. Villagers and the fisher are hidden when `env.night > 0.6`; keepers stay. In `findAction()`, standing near a keeper or a place's door opens that place's screen; standing near anyone else offers a greeting (`people.nearby` / `people.greet`, shown as a toast). To test, loop `game.people.update(dt, time, game.env, game.shore.state, game.shore.state)`; `game.people.current.people` lists the figures.
- **Landing anywhere, and things to find** (`src/finds.js`). `shore.land(isl, ship, useDock)` puts the sailor on the dock, or, for any island when no dock is within reach, on the beach nearest the ship (`findAction()` offers "Row to the beach" when the ship is anchored within 110 m of the shoreline). `shore.state.boat` is where the dinghy waits; `atDinghy()` is a distance check. Code that reads `island.portInfo` while ashore must allow for it being undefined. Every island has one curiosity, set by `find: { kind, angle, dist }` in `ISLANDS` (islands.js turns that into `isl.findSpot` and keeps plants off it) and defined in `KINDS` in finds.js (name, button text, logbook text, model, optional `coins`, `reveal` to chart all islands as rumoured, `ring` for the bell sound). Looking at one calls `finds.discover()` and shows a card via `places.show()`. Three shells per island are auto-collected by walking over them. Progress is in `save.finds` and `save.shells`. The bottle on Little Twin points to the chest on The Twins (120 coins); keep that pairing if either moves.
- **Treasure maps** (`src/treasure.js`). A map is `{ id, island, x, z, tier, coins }` in `save.maps` (at most `MAX_MAPS` = 3, one per island at a time). `gainMap()` picks a random dry, open spot (not on a dock, building, curiosity or steep ground) and a tier (`TIERS`: weathered 150–260, fine 300–460, captain's 650–900 coins). Sources: taverns sell one for `MAP_PRICE` (60), and one bottle a day washes up on a beach chosen from the day number (`save.bottleDay` records the last day it was taken; a tavern line names the island). Maps are listed under the chart (`#chart-maps`) and open as a card via `places.card()`, drawn by `treasure.draw()`: coastline, hills, lighthouse, dock and buildings, an X, no name. When the sailor is standing on that island the map also shows a dot for them. Ashore with any map in hand, `findAction()` offers "Dig here" whenever nothing else is on offer; `treasure.dig()` pays out within 5 m of an X, says "close" within 28 m, otherwise nothing. Chests dug up are counted in `save.treasures`. Later stages should hand out maps through `treasure.gainMap()` too (pirate loot).
- **Economy.** Start: 100 coins, the sloop with a 20-crate hold. Five goods in `GOODS`; a port's price is `base × FACTORS[port] × daily wobble`, and merchants pay 92% of the buy price. Tavern trade tips come from `bestRoute()` so they are always true; keep it that way if prices change. Paints cost 25, sail cloth 60, upgrades 150 (hold +10 crates on any ship) and 250 (sails → `speedBonus` 1.1), brig 900, galleon 2800. `applyUpgrades()` in `main.js` turns `save.upgrades` into actual effects.
- **Discovery.** Sailing within `R × 1.5 + 90` m of an island adds it to `save.discovered` (drawn solid on the chart); hearing of it in a tavern adds it to `save.rumoured` (dotted outline). The chart's world bounds are the `WORLD` constant in `src/chart.js`; widen it if islands are added outside it.
- **Wildlife** (`src/wildlife.js`) is decoration only and never affects the ship: gulls orbit the nearest island and come out to a ship within about 280 m; a dolphin pod joins occasionally in open water when moving (force one in tests with `game.wildlife.pod.wait = 0`); flying fish; three merchant ships that wander between random open-water points, steering away from land and from the player. It disturbs the water through `foamAt` and `audio.splash`, passed in from `main.js`. To test without waiting on frames, call `game.wildlife.update(dt, time, game.ship.state, game.env, game.camera)` in a loop.
- **Audio** (`src/audio.js`) is fully synthesised with Web Audio and can only start after a user gesture; `main.js` calls `audio.start()` on the first pointer/key event. One-shot sounds are triggered from `main.js` (e.g. `audio.anchor`), continuous layers follow the state passed to `audio.update`.

The HUD and all CSS live in `index.html`; elements toggle with the `hidden` attribute (there is an explicit `[hidden] { display: none !important }` rule because several are `display: grid/flex`). **Input.** One on-screen joystick (`#stick`, state in `stick`) and the keyboard (`held`) are combined each frame by `readPush()` into `push` (`x`: right +, left −; `y`: up +, down −, each −1 to 1). At sea `push.x` steers and `push.y` raises or lowers sail. Ashore the push is turned into a ground direction measured from where the camera looks (`walkMove`), the sailor turns to face the way they walk, and pushing left or right also swings the camera (`cam.follow -= push.x × 1.5 × dt`), so one stick walks and turns. Dragging the screen still orbits the camera. New controls should work from both the stick or an on-screen button and a key. Keys: A/D/W/S or arrows (steer and sails, or walk ashore), Space anchor, E context action, C chart, V deck view, T skip three hours, R cycle weather, B try the next ship (temporary), M sound mode. The help overlay in `index.html` and the README controls table list these and need updating when controls change.

### Second plan: treasure, combat, factions and fleets

Decisions the owner made (do not re-ask; build to these):

- **Combat tone: danger in places.** Most of the sea stays peaceful. Pirates keep to their own marked waters. Navy and merchants never attack unless the player attacks them (or is wanted).
- **If the player loses: the ship sinks** with her cargo. The player restarts at port in the sloop and keeps coins and any other ships owned.
- **Cannons: broadsides.** Guns fire out of each side; the player steers to bring a side to bear and presses Fire Port or Fire Starboard. Reload time between broadsides.
- **Factions with reputation:** merchants, navy, pirates. Sinking pirates pleases navy and ports. Attacking merchants makes the player wanted: navy hunts them and prices worsen, until a fine is paid or it fades.
- **Spoils:** floating coins and cargo to sail over; navy bounties on named pirate captains, collected at any harbour; pirates sometimes carry treasure maps; captured ships.
- **Capture: surrender, then claim.** A ship beaten to low health strikes her colours and stops. Sail alongside for a choice: take her as your ship (selling the current one), add her to your fleet if not too damaged, strip her for loot, or let her go. Keep firing and she sinks.
- **Player's fleet:** flagship plus up to three ships that follow in her wake and automatically fight whoever the player is fighting. No orders. Each costs a daily wage; their holds add cargo space.
- **NPC fleets:** pirate squadrons led by a named captain with a bounty, navy patrols, merchant convoys (sometimes escorted), and battles already under way that the player can join or sail past.
- **Treasure maps: a drawn map.** A hand-drawn sketch of one island's outline with an X and a landmark or two, no name. The player works out which island it is and digs at the X.
- **While aboard the player is the ship:** they command and fire but do not walk the deck. Crew figures may be shown doing things. The captain stands at the wheel.
- **Mobile:** one joystick with a following camera (done in stage 1).

Stages, in order. Each is reviewed on the private link before going to `main`:

1. Controls and the captain: joystick for ship and shore, following camera ashore, captain at the wheel. Done and approved. The owner then said to keep going through the stages; still publish each to the private link and tell them what changed, and push to `main` when they approve.
2. Treasure maps: bought in taverns or found in bottles, a map screen, digging at the X, treasure of different sizes. Built; awaiting the owner's review.
3. Cannons and damage: guns on all three ships, broadsides with reload, cannonballs, hull health, visible damage, sinking, repairs at shipwrights, what happens when the player goes down.
4. Factions and enemies: merchants, navy and pirates as proper ships that sail, fight and flee; pirate waters marked on the chart; reputation and being wanted. (The three decorative merchant ships in `wildlife.js` will need replacing by real ships here.)
5. Spoils: floating loot, bounties posted at ports, maps carried by pirates.
6. Capture and the player's fleet.
7. NPC fleets: squadrons, patrols, convoys, battles in progress.

Still open from the first plan: fixing whatever the owner reports from play-testing, and removing the temporary Time, Weather and Ship buttons once they say testing is over.

Preferences the owner has stated: the sailing feel is right as it is; weather is never a threat (a gale is a wilder ride); the peaceful game must remain available, with danger only where the player goes looking for it (this replaced the earlier "no danger at all" rule when combat was requested); features are reviewed on the private link before going public; phone play matters, so every feature needs to work with the joystick and a few large buttons.

Known limits worth remembering: all testing so far has been automated, so motion smoothness, real-phone performance and how the generated audio actually sounds have only been judged by the owner; villagers walk in straight lines between spots and do not avoid buildings or each other; the Time, Weather and Ship buttons are preview tools kept on purpose for now (see the plan).
